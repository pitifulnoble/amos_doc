## 数组和切片的区别
### 数组和切片的相同点

1. 数组和切片都要求全部元素的类型都必须相同
2. 数组和切片的所有元素都是紧挨着存放在一块连续的内存中


### slice和map的区别

1. map中的元素所在内存连续但不一定紧邻（如何理解？
2. 访问元素的时间复杂度都是O(1)，但map更慢

### map的优势
map的key值类型可以是任何可比较类型（如何理解？
对于大多数元素为零值的情况，map可节省大量内存（有点牵强，使用slice还是map由业务决定

### 数组和切片的零值不同

1. 数组的零值是 包含所有元素且每个元素为零值
2. 切片的零值为nil
3. 指针类型的数组和切片直接用类型声明后是nil，不能直接使用

```go
package main

import "fmt"

func main() {
	arr1 := [10]int{}
	fmt.Println("arr1:", arr1)
	var arr2 [10]int
	fmt.Println("arr2:", arr2)

	//有零值
	arr3 := new([10]int)
	fmt.Println("arr3:", arr3)
	var arr4 *[10]int = &[10]int{}
	fmt.Println("arr4:", arr4)

	//为nil,无零值，直接使用会报错
	var arr5 *[10]int
	a := [10]int{}
	arr5 = &a
	fmt.Println("arr5:", arr5)
	fmt.Println(arr3 == arr5)
	var s1 = []int{}
	fmt.Println("s1:", s1)
	fmt.Println("s1==nil:", s1 == nil)
	var ss []int
	fmt.Println("ss==nil:", ss == nil)
	var s2 = new([]int)
	fmt.Println("s2:", s2) //不为nil
	fmt.Println("s2 is nil?:", s2 == nil)
	s1 = append(s1, 1)
	*s2 = append(*s2, 1)
	fmt.Println("s1:", s1)
	fmt.Println("s2:", s2)
	var s3 = make([]int, 1)
	fmt.Println("s3:", s3)
}
```

### 切片和数组传值差异

1. slice1和slice2指向了相同的地址
2. array1和array2指向了不同的地址

```
	slice1 := []int{1, 2, 3, 4}
	slice2 := slice1
	//slice1和slice2指向了相同的地址
	fmt.Printf("slice1 ptr:%p;slice2 ptr:%p\n", slice1, slice2)

	array1 := [4]int{1, 2, 3, 4}
	array2 := array1
	//array1和array2指向了不同的地址
	fmt.Printf("array1 ptr:%p;array2 ptr:%p\n", &array1, &array2)
```

输出：

```
slice1 ptr:0x1400001c060;slice2 ptr:0x1400001c060
array1 ptr:0x1400001c0a0;array2 ptr:0x1400001c0c0
```

> 在 `fmt.Printf("slice1 ptr:%p;slice2 ptr:%p\n", slice1, slice2)` 中，`%p` 打印的是 **切片 `slice1` 和 `slice2` 内部指向底层数组的指针地址**，即它们所引用的底层数组的首地址。以下是具体分析：
>
> 1. **切片的结构**：
>    切片在 Go 中是引用类型，本质是一个包含三个字段的结构体：
>    - `指向底层数组的指针`（决定数据存储位置）
>    - `长度`（元素个数）
>    - `容量`（底层数组总容量）。
>      当使用 `%p` 格式化切片时，输出的是其内部 `指向底层数组的指针` 的值，即底层数组的首地址。
> 2. **赋值行为**：
>    `slice2 := slice1` 仅复制切片的结构体（指针、长度、容量），不复制底层数组。因此 `slice1` 和 `slice2` 的内部指针指向同一底层数组，打印的地址自然相同。
> 3. **与数组的对比**：
>    数组是值类型，`array2 := array1` 会完整复制数组内容，`&array1` 和 `&array2` 是两个独立数组的地址，故输出不同。而切片打印的是底层数组的指针，与切片变量自身的存储地址无关。

- **原理**：切片是引用类型，赋值时仅复制切片头（包含底层数组指针、长度、容量），不复制底层数据。因此 `slice1` 和 `slice2` 指向同一底层数组。
- **原理**：数组是值类型，赋值时会完整复制整个数组内容，生成独立副本。因此 `array1` 和 `array2` 拥有不同的内存地址。

## 切片底层数据结构是什么？有什么特性？

### 数组的存储结构

是内存中连续的一段内存

### 切片的数据结构

切片是一个结构体主要有3个元素

```
ptr # 指针，指向内存中存放数据的首地址，和数组类似
len # 长度
cap # 空间
```

### 切片的赋值过程

单纯拷贝ptr, len, cap。实际数据没有拷贝，只拷贝了指针地址等信息。

## 哪些类型可以作为map的key？
只有可比较类型可以做map的key。
slic、map、struct是不可比较的，所以不能作为key。

### float作为map的key有什么问题？
表现：相近的float的key会互相覆盖。
原因：map会把floatkey转换成uint64。

## map的底层实现是什么？
哈希表。
采用了更高效的链地址法结合桶（Bucket）结构来解决哈希冲突，同时通过渐进式扩容等机制优化性能。其核心设计围绕两个关键结构体：hmap（哈希表的元信息）和bmap（桶，存储键值对）。

1. hmap（哈希表的顶层结构）
hmap 是 Go 中map的实际表示，存储了哈希表的全局信息，定义大致如下（简化版）：
```go
type hmap struct {
    count     int           // 已存储的键值对数量（len(map)的结果）
    B         uint8         //  buckets数组的大小 = 2^B（例如B=3时，buckets大小为8）
    buckets   unsafe.Pointer // 指向buckets数组（每个元素是一个bmap）
    oldbuckets unsafe.Pointer // 扩容时的旧buckets数组（用于渐进式迁移）
    // 其他字段：如哈希函数、溢出桶数量、标记位等
}
```
- B 决定了buckets数组的大小（2^B），例如B=5时，buckets长度为 32。
- oldbuckets 用于扩容过程中临时存储旧的buckets，避免一次性迁移带来的性能抖动。

2. bmap（桶，存储键值对的单元）
bmap 是哈希表中的 “桶”，每个桶最多存储8 个键值对，结构大致如下（简化版）：

```go
type bmap struct {
    tophash [8]uint8  // 存储每个键的哈希值高8位（快速匹配用）
    // 后续隐式字段（编译期动态生成）：
    // keys [8]keyType   // 8个键
    // vals [8]valType   // 8个值
    overflow uintptr  // 指向溢出桶（当桶内8个位置满时，用溢出桶扩展）
}
```

- tophash：存储每个键的哈希值高 8 位（哈希值共 64 位），用于快速判断键是否可能在当前桶中（减少完整键的比较次数）。
- 键值对存储：keys和vals数组分开存储（而非键值对交替），目的是减少内存对齐带来的空间浪费（例如键是 int64，值是 int8 时，分开存储更紧凑）。
- overflow：指向另一个bmap（溢出桶），当当前桶存满 8 个键值对时，新的键值对会存入溢出桶，形成链表（解决哈希冲突）。
