## SpringBoot的主干

SpringBoot存在主干，也就是主要要解决的问题(意味着不是全部问题)。

IOC实现：容器 加入容器(最复杂最重要) 注入



SpringBoot的目的：

抽象意义上：将控制权交给用户。实现灵活的OCP

1. spring项目因为IOC的原因，代码调用连不清晰，这是阅读其他源码困难的原因。



## 注解方式:将对象加入容器

### 最常用@Component和@Autowired

加入容器@Component：

```java
import org.springframework.stereotype.Component;

@Component
public class HiComponent {
    public void p() {
        System.out.println("Component");
    }
}
```

注入@Autowired：

```java
import jakarta.servlet.http.HttpServletResponse;
import org.example.amosproject2.component.HiComponent;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestMethod;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("v2")
public class ActionController {
    @Autowired
    private HiComponent hiComponent;

    @RequestMapping(value = "/test", method = {RequestMethod.GET, RequestMethod.POST})
    public String printBanner(HttpServletResponse response) {
        System.out.println("Hash Code: " + System.identityHashCode(hiComponent));
        return "hello 你好";
    }
}

```

注意：多个class都注入HiComponent时，是同一个对象。它的``System.identityHashCode(hiComponent)``是相同的



### 其他注入注解

```
@Service
@Controller
@Repository
@Configuration
```

上述注解在实现上都会调用@Component

@Configuration和其他注解不同，它可以一次加入多个bean

## Spring中class实例化的机制和时机

默认配置下，spring在启动时立即实例化，并注入对象。

可以在对象上打@Lazy来让这个对象延迟实例化(如果这个对象被其他对象注入，且那个对象要立即实例化，这个lazy就不会生效。需要在调用连的最上层就打上@Lazy)



## 常见注入语法

### 字段注入

这种注入方法，编辑器不推荐，会有警告


### 构造函数注入

```java
@RequestMapping("v2")
@RestController
public class ActionController {
    private HiComponent hiComponent;

    @Autowired
    public ActionController(HiComponent hiComponent) {
        this.hiComponent = hiComponent;
    }

    @RequestMapping(value = "/test", method = {RequestMethod.GET, RequestMethod.POST})
    public String printBanner(HttpServletResponse response) {
        System.out.println("Hash Code: " + System.identityHashCode(hiComponent));
        return "hello 你好";
    }
}
```

### Setter注入


## 注入匹配机制byType和byName

### byType和byName

注入对象时，先通过类型(type)推断，当有多个实现类(实现同一个接口)时，再通过成员变量命名决定注入哪一个对象。

当多个对象不能通过名称推断注入时IDE会提示错误，springboot启动也会报错。

举例：

```java
public interface HC {
    public void q();
}

@Component
public class HelloComponent implements HC {
    @Override
    public void q() {
        System.out.println("Hello Component");
    }
}

@Component
public class HiComponent implements HC {
    @Override
    public void q() {
        System.out.println("Hi Component");
    }
}
```

```java
@RestController
@RequestMapping("/v1/")
public class BannerController {
    @Autowired
    private HC hiComponent;

    @RequestMapping(value = "/test", method = {RequestMethod.GET, RequestMethod.POST})
    public String printBanner(HttpServletResponse response) {
        hiComponent.q();
        return "hello 你好";
    }
}
```

1. 首先通过HC类型有2个实现类
2. 接着通过变量名称``hiComponent``决定注入``HiComponent``这个具体类型
3. 通过``byName``来注入对象，就已经依赖了具体(接口失去了意义)，不推荐

### 我们也可以使用@Qualifier注解来修改byName机制

```java
@RestController
@RequestMapping("/v1/")
public class BannerController {
    @Autowired
    @Qualifier("hiComponent")
    private HC hc;

    @RequestMapping(value = "/test", method = {RequestMethod.GET, RequestMethod.POST})
    public String printBanner(HttpServletResponse response) {
        hc.q();
        return "hello 你好";
    }
}
```

## @Configuration配置

@Configuration配置的作用也是创建对象到容器中的。

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ConfigComponent {
    @Bean
    public HC GenComponent() {
        return new MyComponent("amos");
    }
}

public class MyComponent implements HC {
    private String name;
    public MyComponent(String name) {
        this.name = name;
    }
    @Override
    public void q() {
        System.out.println("My Component " + this.name);
    }
}
```

### @Configuration的实践

1. 我们需要自己创建对象，这个过程中我们可以对对象创建做一些自定义事项。
2. 对象创建过程中的变量一般从配置文件中获取(配置环境来区分不同的环境(线上/测试环境))
